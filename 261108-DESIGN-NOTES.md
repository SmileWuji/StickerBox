# StickerBox design notes (2026-11-08)

Notes from the first design chat. Nothing is built yet; these are the agreed direction and the
reasoning behind it, to be turned into a build plan, the CLI's docs, and the skills that ship with
it. Notes are `YYMMDD-XXX.md`; newest wins when two disagree.

## 1. What it is

A mini GuidedSticker: a generic, local image store driven by a CLI, meant to be operated by an AI
agent and, after enough use, readable by a human. The storage is the product: a SQLite database,
a text manual that describes it, and the image files.

First consumer: the QQ bot in `../QQBot` (大肥鱼), which has bash. It runs two instances:

| profile | images | tags | box does |
|---|---|---|---|
| `sticker` | normalised to 512 px | controlled vocabulary, one skill per tag category | OCR assist, pHash, keyframes, vocabulary enforcement, search |
| `gallery` | original size kept | free-form, entirely at the bot's discretion; no skills | sha256, pHash, local features (SIFT), keyframes, dedup relations, search |

The existing QQBot `index.jsonl` files are migrated by a prompt the owner writes in QQBot; the box
needs no importer for them.

### Lineage (reuse ideas, not code wholesale)

- `../GuidedStickerBootCamp`: keyframe extraction and 64-bit pHash; defaults measured in
  `260917-CORPUS-NUMBERS.md`.
- `../GuidedStickerObservatory`: OCR. The benchmarked rescue tier is "RapidOCR text + image to a
  VLM, text marked unreliable", and a noise gate (`service/noise.py`).
- `../GuidedStickerTagger-SNAPSHOT-260920`: one narrow question per tag class; character ID by
  vision does not work on this corpus (1 TP in 150); hair colour is wrong on greyscale input; 64%
  of "pose" tags were camera framing.
- `../260622-PerceptualHash-Brainstorming.txt`: block pHash and ORB/SIFT + RANSAC for matching
  stills to animation frames.
- `../GuidedStickerPostOffice/260919-Opus-Consultation.md`: Chinese two-character queries defeat
  FTS5 trigram; use `LIKE` for short queries.

## 2. The CLI enforces, the prompt guides

The agent will drift (`无语` and `无语了` side by side after a few hundred stickers), so the rules
live in the CLI, not only in the prompt.

- `tag add` accepts existing tags only. An unknown value is rejected and the error lists the
  nearest existing tags (fuzzy match and aliases), so the agent corrects itself in the same turn.
- Creating a tag is deliberate: `tag new <category> <value> --means "..."`. No tag without a
  definition.
- `tag alias` and `tag merge` are the cleanup path.
- A tag row: category, canonical value, definition, aliases, optional parent. Parents give the
  multi-layer dictionary (情绪 → 负面 → 嫌弃).
- The `gallery` profile skips enforcement; its tags are free-form.

## 3. The manual

The text context file is the user manual for both the agent and a human. Half of it is generated
so it cannot drift from the database:

- hand-written: what each category is for, conventions, examples;
- generated by `box manual`: the vocabulary (tags, definitions, aliases, parents, counts).

## 4. OCR

No OCR model in the box. The harness model reads the image itself, guided by a skill with a prompt,
examples and a required JSON shape. The box runs RapidOCR on ingest and hands its text to the agent
as an unreliable hint, which is the order the Observatory benchmark found best. A watermark such as
a pack's `@handle` is attribution and is kept as text. DeepSeek's vision has not been benchmarked for this;
spot-check a few dozen stickers before trusting it.

## 5. Tag categories (sticker profile)

One skill per category, following the Tagger's "one narrow question per class". Keep the set small
because every loaded skill costs context. Candidate set, chat-oriented:

- text: the on-image text (section 4)
- emotion and intent: 无语, 嫌弃, 卖惨; what a chat bot actually searches by
- character and series: prefer the source's metadata (pack name, site data) over vision
- visual content
- usage note: when to send it

## 6. Duplicates

Three levels, cheapest first:

| level | catches | misses | cost |
|---|---|---|---|
| sha256 | identical file | everything else | free |
| pHash | recompression, resize, format change, light filters | crop/zoom, rotation, large overlays | 8 bytes, microseconds |
| local features (SIFT + RANSAC) | crop/zoom, rotation, partial overlays, a picture screenshotted inside the QQ UI | flat-colour art with few keypoints | tens of KB, milliseconds per pair |

pHash shrinks to 32×32 first, so size differences do not matter to it; its weakness is geometry.
In a chat gallery the common duplicate is a crop or a screenshot, so SIFT does the real work in
the `gallery` profile while pHash stays primary in `sticker` (flat art gives SIFT few keypoints).
SIFT is in mainline `opencv-python` since 4.4 (patent expired 2020); no weights, no torch.

Caveats: QQ screenshots share UI chrome and text-heavy images give false matches on glyphs, so the
inlier threshold must be tuned on real data, and images with too few keypoints skip SIFT.

The RANSAC homography says what the relation is (crop and which region, zoom factor, rotation).
The CLI reports it rather than rejecting: "looks like `g_0142`, a 40% crop at 2.1× zoom". The agent
decides to skip, keep, or keep linked; a zoomed crop of a meme is often a different reaction image.

Animated images: keyframes first (BootCamp), then pHash and SIFT per keyframe; a still matching a
keyframe is linked to its animation.

Neural embeddings (DINOv2, CLIP) would cover every case and add "find similar", but need torch and
weights on a small droplet. Later, not v1.

## 7. Storing features

Expected scale: thousands of images.

Descriptors go into SQLite as BLOBs, in a separate file (`features.sqlite` beside `box.sqlite`):

```sql
CREATE TABLE feature (
  image_id   TEXT NOT NULL,
  frame      INTEGER NOT NULL DEFAULT 0,
  extractor  TEXT NOT NULL,      -- e.g. "sift-v1:300kp"; stale rows are rebuilt by `box reindex`
  n          INTEGER NOT NULL,
  kp         BLOB NOT NULL,      -- n×2 float32, needed by RANSAC
  desc       BLOB NOT NULL,      -- n×128 uint8
  PRIMARY KEY (image_id, frame)
);
```

300 keypoints is about 40 KB per image. SQLite reads blobs under about 100 KB faster than separate
files, and the cap removes the reason the June note had for external files. The separate file
keeps the human-facing database small, is a rebuildable cache (`box reindex`), and can be left out
of backups. pHash is a plain INTEGER in the main database.

## 8. Comparing

A B-tree answers equality and ranges on a sortable key. Nearest neighbour in 128 dimensions, and
Hamming distance on pHash, cannot be expressed that way, so SQLite stores and numpy/OpenCV compares.

Insert-time dedup:

1. sha256 lookup (indexed); then all pHashes loaded as one integer array, Hamming by vectorised
   XOR and popcount. A near-identical hit stops here.
2. Shortlist by voting: stream descriptors in batches of about 200 images, stack each batch with an
   owner array, take nearest neighbours of the new image's descriptors, one vote per neighbour's
   owner. Keep the top three or so. Batching bounds memory.
3. Verify: per pair, ratio test, then `cv2.findHomography` with RANSAC; inliers above the threshold
   mean the same picture, and the homography gives the relation.

No ratio test in step 2: if the pool already holds two copies of an image, best and second best
tie and every match would be rejected. The ratio test belongs in the pairwise step only.

Cost at 3,000 images: about 300 × 900k × 128 multiply-adds, roughly 35 GFLOP, a few seconds on one
core with BLAS. Fine on insert; search never touches features.

### Letting SQL do the shortlist (upgrade path)

Turn closeness into exact matches, which an index can serve:

- pHash, multi-index hashing: split the 64-bit hash into four 16-bit indexed columns. Within
  Hamming 3, at least one chunk is identical (pigeonhole), so
  `WHERE c0=? OR c1=? OR c2=? OR c3=?` gives candidates; exact Hamming on those rows.
- SIFT, visual words: k-means a vocabulary of about 10,000 centres once and ship it as a file
  (pinned by `extractor`); each descriptor becomes a word id; store `image_word(word, image_id)`
  with an index on `word`; the vote is
  `SELECT image_id, COUNT(*) FROM image_word WHERE word IN (...) GROUP BY image_id ORDER BY 2 DESC LIMIT 5`.
  Costs a training step and a little recall. `box reindex` can fill it from stored descriptors,
  so adding it later needs no image migration.
- A vector extension (`sqlite-vec`) is still brute force in C, needs one row per descriptor
  (about 900k rows) and 300 queries per insert. More machinery than visual words, no gain here.

Start with the batched scan; visual words when it gets slow.

## 9. Cleanup

- Matches found at insert are recorded: `relation(a, b, kind, inliers, transform)`. `box dupes`
  reads that table (clusters with the relation and a suggested keeper) instead of comparing all
  pairs; a full rescan only after `reindex`.
- `box stats`: size, count, untagged images, images never sent.
- A scheduled maintenance session in the consumer (like QQBot's dream and sticker-browse sessions)
  works through `box dupes` and decides what to keep.
- Idea: during a dream the agent may explore the store and propose vocabulary changes (merges,
  aliases, new parents, retired tags) through the same CLI verbs, so every change is enforced and
  shows up in the manual.

## 10. Decided (2026-11-08, second round)

- The CLI is `sticker-box`. This repo is standalone; QQBot is one user among possible others and
  the owner wires it in on the QQBot side (dsh container, so Python, OpenCV and RapidOCR go into
  that image).
- An instance is a directory at a configurable path (QQBot: `data/sticker-box/stickers/` and
  `data/sticker-box/gallery/`) with this tree:

  ```
  <instance>
  ┣━ temporary/
  ┣━ persistent/
  ┣━ box.sqlite3
  ┗━ README.md        warning: modify this directory only through the sticker-box tool
  ```
- SIFT features live in `box.sqlite3` (supersedes the separate `features.sqlite` of section 7):
  nothing to rebuild, at about 40 KB per image. Only the gallery preset computes them.
- Every image has a `license` field in every preset; `unknown` is a valid value when the caller
  cannot tell.
- Third use case, a buffer: items in `persistent/` expire (e.g. after 60 minutes) and are removed
  by the `clean` command (section 11). Other candidate use cases were judged duplicates of sticker
  or gallery.
- Many models (DeepSeek included) have no video input and read an animation through its keyframes.
- No conversion in the box: the caller converts, the box only validates against the instance's
  policy.
- One language per instance, recorded in the database (e.g. `meta(key, value)` with
  `language = zh-Hans`). Every tag, definition and description is in that language. Exceptions:
  OCR text stays verbatim, and a language-specific meme phrase may keep its original language. Any
  other language need is the agent's job (translate at query or display time), not the store's.
- An instance is one SQLite file, a temporary directory and a persistent directory. Incoming files
  land in the temporary directory, which can be emptied at any time; adding an image moves it into
  the persistent directory. Persistent names are SHA256 plus date.
- No packs. A pack is a tag.
- The first vocabulary is bootstrapped by the agent from the stickers it tags, not seeded by hand.
  The vocabulary starts open (new tags allowed, each with a definition); after a cleanup pass that
  merges near-duplicates it is locked, and from then on a new tag needs an explicit `tag new`.
- Animated formats: WebP is fine for QQ; WebM is not and becomes GIF.
- Adding is two steps: `stage` copies into the temporary directory and reports the OCR hint and
  duplicates without touching the database; `commit` moves the file into the persistent directory
  and writes the row. Emptying the temporary directory can never break the database.
- Persistent names: `store/<yyyymm>/<yyyymmdd>-<sha256>.<ext>`, dated by first add; sha256 is
  checked before the move, so re-adding never makes a second copy.
- Provenance (e.g. a Telegram pack URL) is a fixed field on the image, not a tag.
- The CLI checks the script of new tags (kana, Han, Latin) against the instance language and warns
  rather than rejects, since kanji-only Japanese looks like Chinese.

### Third round

- The tool never fills tags, text, descriptions or notes; the bot or a human does.
- The repository will be open source: no third-party or confidential content. Tests use two data
  directories, a committed generic one and a git-ignored private one fed from
  `../GuidedSticker-Project-TestData`, `../private/pack-a/` and
  `../private/pack-b/`.
- Security code reviews at M5, M7 and M8 of the build plan (`AGENTS.md`).
- Tagging skills recommend few reference sources with a clear precedence: bangumi-data for anime
  and subculture names, then Wikipedia, IMDb and similar; image banks for examples (not reverse
  image search) such as Safebooru, Giphy, Pinterest. These are the agents' preferences, not box
  policy, and are kept as agent notes rendered into the box's `README.md` under "To agents".

## 11. Policy, presets, and the item lifecycle

### Policy

Each instance stores a policy in `box.sqlite3`: a description shown to users, the instance
language, and named rules with parameters. The checks are code inside `sticker-box`; the directory
holds no scripts (a box that ran code found in its own directory would run whatever anyone with
write access put there, and copied scripts would never get fixes). The policy changes only through
`sticker-box policy set`, each change logged. `README.md` is generated from the policy and the
vocabulary, so the manual cannot drift.

Rule kinds:

1. fields, and which are required (`license` exists in every preset, `unknown` allowed, free text)
2. tag categories and how many values each takes (exactly one, at least one, any)
3. file rules: formats, max and min size, bytes, duration, whether animation is allowed
4. vocabulary mode: free, open then locked, locked
5. on duplicate: reject, report and let the agent decide, link
6. retention: expiry after a time since add, total-size cap removing the oldest first

Presets:

| preset | files | tags | duplicates | retention |
|---|---|---|---|---|
| `telegram-sticker` | Telegram sticker spec (verify the numbers against Telegram's current docs) | text, emotion, usage note; open then locked | sha256, pHash | none |
| `gallery` | any size | free-form | sha256, pHash, SIFT; report | none |
| `buffer` | any | none required | sha256, pHash | e.g. 60 minutes, optional size cap |

A meme library is a documented example rather than a preset: the sticker tag rules with the file
rules switched off (the box does not convert, so an ordinary meme JPG would fail the sticker spec).
The buffer is a start on short-lived media but will not replace QQBot's temporary media folder,
which also holds long videos, music and other types.

### Lifecycle

- `stage` is the "upload picture" step, like the command center's `PUT /images`: the file is in the
  system and can be referenced by its sha256, but `box.sqlite3` has no row for it. The analysis
  (sha256, pHash, keyframes, RapidOCR hint, SIFT, file-rule results) is written as a sidecar next to
  the file in `temporary/`, tagged with the extractor version, so `commit` reuses it and recomputes
  only when the sidecar is missing or stale.
- `commit` validates fields, tags and file rules, moves the file into `persistent/` and writes the row.
- Nothing is cleaned implicitly. `clean` empties `temporary/`, and also removes expired
  `persistent/` items when the policy has a retention rule. By default it only touches staged files
  older than a grace period, so another session's in-flight stage is not pulled away; `--all`
  removes everything staged.
- Thresholds fail loudly. When a write (`stage`, `commit`) would put the box over a policy limit
  (size, count), it fails with an error that names the limit, the current usage, and the `clean`
  command to run. Reads and search never fail on a threshold. An expired item stays readable until
  cleaned and is flagged `expired` in output.
- `--auto-cleanup` on a write is the caller's opt-in: before writing, remove expired items, then,
  if still over a limit, the oldest items until under it. The output lists everything removed.
  The limits apply to any preset that sets them (e.g. a gallery size cap), not only the buffer.
- Transfer between boxes is `stage --from <other box> <id>`: the item is staged in the destination
  with its analysis and licence carried over, and the destination validates it at `commit` like any
  other item. No separate validation path; the source item stays until it expires or is removed.
- Every command prints JSON for an agent or readable text for a human, by flag.
- `sticker-box frames <id>` returns a contact sheet: the keyframes tiled in one image, labelled with
  frame number and time, so a model without video input reads an animation in one image call.
  Available in every preset.
